# 拾光空间数据库设计与评估

目标环境：`slogan-3gf3tz4nf12fa5ef`（ap-shanghai，现有 MySQL 8.0）。实际数据库名与环境 ID 相同；已通过只读查询核实。

## 数据与权限

- `shiguang_spaces`：名称、封面、信件、绑定返图空间、启用状态和软删除时间。
- `shiguang_members`：用户 ID 全局唯一，空间与男/女角色唯一。永久保存，不随空间或账号删除级联删除；空间头像和名称独立保存。
- `shiguang_entries`：纪念日、许愿池、心约、絮语、心情、拾物的公共审计字段与各自 JSON 内容。通过 kind 区分；心情增加日期唯一约束，其他记录日期为空。
- `shiguang_replies`：絮语回复；删除絮语时数据库级联删除回复。
- `shiguang_prizes`：可编辑奖池，与已发券的名称、内容快照分离。
- `shiguang_wallets`、`shiguang_grants`：每人可用次数及不可变的给予记录。
- `shiguang_tickets`：抽奖/赠送形成的不可变快照，仅允许提供人从待使用变更为已使用。
- `shiguang_operations`：请求 UUID、操作者、操作类型、参数摘要及结果；相同请求返回原结果，不重复扣次/赠送。
- `shiguang_media`：媒体归属、类型及存储标识。对象加密存储，只有鉴权后的成员接口可解密读取；管理媒体与成员私密内容区分。

所有新表不加入通用 `/api/db/query` 白名单；统一通过拾光后端接口访问，管理员仅能管理空间资料与成员空间资料，不能读取私人玩法内容。新表包含平台保留 `_openid`，本项目自有会话鉴权不依赖该字段。新表客户端权限保持关闭。

## 一致性

1. 创建空间存储过程在一个事务中检查账号、创建空间、插入两名成员和初始化钱包；任一用户已被占用则完整回滚。
2. 奖券操作存储过程先锁空间行，再检查成员/状态并检查请求去重。抽奖扣次和奖券快照一起提交；每项等概率且可重复抽中。
3. 给予次数、直接赠券及核销同样走事务与幂等记录。请求 UUID 由客户端生成，网络失败后重试复用。
4. 软删除只更新空间状态，不删除成员及内容。成员表不关联 users 的级联删除，保留账号删除后的历史归属。
5. 内容更新保留创建人/时间，更新使用版本号防止双方覆盖。北京时间由后端生成，客户端不能指定心情记录日期。

## 接入与验证

仅新增表、索引和存储过程，不迁移现有业务表；拾光页面由内置配置提供，页面中心保存时按既有机制落库。迁移文件先落盘，远端执行需明确授权。部署前本地检查：类型/构建、权限矩阵、心情日期边界、抽奖并发与网络重试、两端入口切换、图片与录音。

### 运行与部署约束

- 两个事务过程通过腾讯云官方 `tencentcloud-sdk-nodejs-tcb` 的 `RunSql` 调用；数据模型 SDK 的 `$runSQLRaw` 不支持 `CALL`。普通查询仍使用现有 SQL 执行器。沿用服务端 `CLOUDBASE_ID`、`CLOUDBASE_SECRET_ID`、`CLOUDBASE_SECRET_KEY` 和地域配置，不保存原生数据库账号密码。
- 部署账号需拥有目标环境的 `tcb:RunSql` 权限；当前本地服务端凭据已验证可以调用。网络失败后客户端保留请求 UUID，以便安全重试。
- 媒体密钥优先使用 `SHIGUANG_MEDIA_SECRET`，未设置时兼容使用 `CLOUDBASE_SECRET_KEY`。首次存储媒体前应确定长期稳定的密钥并安全备份；切换或轮换密钥前必须迁移历史媒体，否则旧图片和录音无法解密。密钥仅在服务端使用。
- 2026-11-17 已按授权在目标环境创建 10 张表和 2 个事务过程，10 张表的客户端权限均核验为 `ADMINONLY`。原生 MySQL 仅用于过程安装，应用运行不依赖原生连接。
- Web 拾物采集复用现有内测采集组件，通过存储适配器接入空间权限和持久化。小程序使用原生图片采集表单读写同一份记录；Web 的浏览器抠图模型不在小程序执行。

页面延用 `#FFFBF0` 背景、`#5D4037` 正文、`#FFC857` 强调、`#FFFFFF` 内容底与 `#B45345` 提示；字体沿用 ZQKNNY/YouYuan。采用柔和手账风格，4/8/12/16/24/32 间距，Web 以现有 sm/md 断点和 max-w-4xl 容器适配，后台保持现有操作布局。首页一级壳，内测切换二级壳，各玩法固定二级壳。
