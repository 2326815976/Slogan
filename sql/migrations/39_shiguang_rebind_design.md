# 拾光空间删除后重新绑定

适用环境：`slogan-3gf3tz4nf12fa5ef`，现有 MySQL。用户于 2026-11-18 确认本规则，替代迁移 38 中“软删除后永久占用成员”的规则。

## 规则与实现

- 仅软删除释放占用；启用、禁用空间均占用成员，空间内仍不可换绑。
- 成员和钱包改为 `(user_id, space_id)` 联合主键，旧资料、创建时间和余额原样保留。钱包外键同时校验用户和空间。
- 成员增加 `released_at`，以及根据该字段生成的 `active_user_id`；后者的唯一索引保证并发创建也不能将同一用户绑定到两个未删除空间。已释放记录生成 NULL，可保留多个历史空间。
- 删除接口使用一条多表 UPDATE 原子更新空间状态和两名成员的释放时间，继续使用空间版本号防止并发覆盖。
- 新建使用新增过程 `shiguang_create_v2`，先释放所选用户在已删除空间中的遗留占用，再验证可绑定性，事务内创建空间、成员与零余额钱包。兼容迁移与新版本上线之间旧接口的删除操作。
- v1 创建过程保留，旧后端在过渡期间仍会拒绝历史成员重建，不会错误放行。奖券过程现有全部读写均包含 space_id，不需要修改。
- 用户选项使用 EXISTS 检查未删除空间，避免历史成员重复产生选项。两端删除成功后刷新用户选项。
- 现有成员权限、内容、奖券、媒体与钱包查询均以有效空间 ID 隔离；删除空间不能恢复访问，新空间不继承旧空间的数据和抽奖机会。

## 迁移顺序与风险

执行 `39_shiguang_rebind.sql` 的 statement-break 分段，按序执行且不把过程体按分号拆开。DDL 自动提交，执行前保存两张表的结构和数据备份。中途失败先核对已完成步骤，不盲目重跑整个文件。

1. 钱包改联合主键，暂移除旧单列外键。
2. 成员改联合主键，增加释放时间与有效绑定唯一索引。
3. 恢复钱包的联合外键。
4. 仅回填已删除空间成员的释放时间，不改变未删除空间绑定。
5. 新增 v2 创建过程；核验索引、外键和历史数据行数，再发布代码。

不删除业务记录、不更新手机号、不更改内容及奖券。DDL 可能短暂等待表锁，应在低流量时执行。创建过程需原生 MySQL 安装（现有 CloudBase RunSql 不支持 CREATE PROCEDURE）；普通 DDL、回填和核验优先使用 CloudBase 工具。

## 验证与回退

本地真实 MySQL 验证：删除重建、禁用占用、不同账号约束、并发创建、请求重试、旧数据隔离、旧接口删除的兼容处理、删除版本冲突、两端选择列表刷新。

2026-11-18 验证结果：MySQL 8.0.42 上迁移和上述服务测试通过；8 组、每组 6 个并发创建请求均恰好一个成功，联合外键和有效绑定唯一索引有效。Web 实际 React 页面在浏览器中验证删除后立即重新选择成员；小程序使用实际组件脚本验证删除后刷新选项。TypeScript 检查通过。远端只读核验：当前有 1 个已删除空间、2 条待释放成员记录，现有奖券过程的钱包读写均按空间隔离。

尚未产生重新绑定记录时，可在备份核验后恢复旧结构。产生历史多空间记录后不能直接恢复单用户主键，否则冲突；应先停止新建入口，保留新结构和数据并向前修复。旧代码会拒绝重建但不泄露历史空间数据。
