# 心意奖券图片与赠送

## 规则

- 待赠卡券创建时指定对方为接收人，双方可见。仅提供人可编辑、删除或送出，单张卡券只能送出一次。
- 转盘奖项和待赠卡券可选填图片。后端只接受提供人本人在当前空间上传的图片引用。
- 送出或抽中时，事务把名称、内容、图片和双方身份写入奖券快照。送出后在「我们的奖券」查看。提供人可兑现并记录使用时间。
- 抽奖、赠送复用现有空间行锁和请求去重表。赠送额外检查待赠状态和版本，并在同一事务内发券。钱包扣减在奖池为空时随事务回滚。

## 迁移

1. 在现有 CloudBase MySQL 核对迁移 38、39 的对象与目标库。选择低流量时段并准备数据库备份。
2. 执行 `40_shiguang_ticket_images_and_gifts.sql`，按 `-- statement-break` 分成四条完整语句。存储过程用原生 MySQL 客户端安装。前两条为一次性 `ALTER TABLE`，如果中途失败，按 `INFORMATION_SCHEMA.COLUMNS` 确认执行进度后再续跑。
3. 确认两张表的 `image` 字段、待赠表和新过程存在。用测试空间核验抽奖、赠送与兑现后，再发布 Web 后端和小程序。旧奖项及奖券的图片默认为空，旧端的直接赠送和历史奖券保留兼容。

DDL 可能等待表的元数据锁。应用需要回退时可回退 Web 后端和小程序版本，并保留新增对象和已经生成的奖券。保留原 `shiguang_ticket_v1`，前后端发布期间仍可执行原有赠送次数、直接赠送和核销。
